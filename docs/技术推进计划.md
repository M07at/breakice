# 技术推进计划（线性方案）

> 目标：在**不动现有可用版本**的前提下，一周内产出一个外部玩家可以试玩的版本；随时可以退回验收版。
> 本文件只描述技术步骤顺序，不涉及人员分工。

---

## 0. 起点与硬性约束

| 项 | 现状 |
| --- | --- |
| 代码 | `master`，HEAD `6fcdfa4`，已推送 Gitee |
| 版本标记 | 标签 `v1.0-验收版`（已创建并推送） |
| 后端 | Supabase 云（PostgreSQL + RLS + Storage + Realtime + 5 个 Edge Functions） |
| 前端 | uni-app 3 + Vue 3 + TS，可构建 `mp-weixin`（0.99 MB）与 `h5`（1.37 MB） |
| 质量门 | 类型检查、313 个单元测试、构建、体积、密钥扫描、构建产物新鲜度 |

三条不可违反的约束：

1. `master` 任何时候都能构建、能跑；实验性改动走独立分支或独立目录。
2. 现有 Supabase 云端数据与配置在验证通过前**不修改**。
3. 任何一步失败，都能在不依赖记忆的情况下按文档退回 `v1.0-验收版`。

## 1. 三层回滚保险（第 0 天完成）

### L1 代码层

```bash
git tag -a v1.0-验收版 -m "验收通过的版本"
git push origin v1.0-验收版
```

回滚方式：

```bash
git checkout v1.0-验收版          # 只看
git checkout -b hotfix/rollback  # 或基于标签开分支
```

### L2 产物层

把当时能跑的东西**存成文件**，避免"代码能回滚但环境和参数丢了"：

```
backup/v1.0/
  mp-weixin.tar.gz      # app/dist/build/mp-weixin 完整产物
  h5.tar.gz             # app/dist/build/h5 完整产物
  source.zip            # 源码快照（git archive 生成）
  env.snapshot.txt      # 当时使用的环境变量名与取值来源（不含密钥明文）
  db-schema.sql         # 数据库结构导出
```

生成命令：

```bash
git archive --format=zip -o backup/v1.0/source.zip v1.0-验收版
tar -czf backup/v1.0/mp-weixin.tar.gz -C app/dist/build mp-weixin
tar -czf backup/v1.0/h5.tar.gz -C app/dist/build h5
```

> `backup/` 不提交到仓库，放本地 + 一份网盘。原因是里面有体积大的产物。

### L3 数据层

| 对象 | 备份方式 | 频率 |
| --- | --- | --- |
| 数据库结构 + 数据 | `pg_dump`（或 Supabase 后台导出） | 改动前后各一次 |
| Storage 文件 | 画作目录整体下载 | 每周 |
| 迁移回滚 | `supabase/rollback/0023~0025*.sql` 已有，补齐 0026 | 一次性 |

**验收标准**：能在 10 分钟内把项目恢复到"验收版可构建、可运行"的状态，并且演练过一次。

## 2. 双设备开发调试（第 0 天，半天）

目标：两个人各自在自己的电脑上改代码、在自己的手机上跑真机，互不干扰。

1. 微信公众平台后台 → 成员管理 → 开发者，添加第二个微信号（需要对方微信号）。
   - 坑：开发者名额有限，别把名额浪费在不写代码的人身上；只试玩的用"体验成员"。
2. 各自拉代码后创建本地环境文件（不进 git）：

```bash
# app/.env.local
VITE_SUPABASE_URL=<同一个云实例地址>
VITE_SUPABASE_ANON_KEY=<同一个 anon key>
```

3. 验证方式：两人分别 `npm run dev:mp-weixin`，用**各自的手机**（不同微信账号）进同一个房间，确认能看到对方的准备状态、能开局。

**完成标志**：一台电脑 + 一台手机、两台电脑 + 两台手机都能联机跑通一局。

**回滚**：删掉 `.env.local` 即回到默认行为。

## 3. 一周线性计划

### Day 1 — H5 能不能跑联机（关键分叉点）

H5 是"给外部玩家试玩"最短路径：一条链接，任何人手机浏览器打开，不需要加成员、不需要备案。

要做的事：

1. `npm run build:h5`，用本地静态服务器起起来。
2. 用两个浏览器标签（无痕 + 普通）模拟两个人，进同一个房间。
3. 重点验证身份问题：H5 没有微信登录，项目当前用本地身份兜底（`LOCAL_USER_ID`），要确认后端能接受，否则联机不可用。

**完成标志**：两个标签能进同一房间、能开局、能看到对方操作。

**分叉决策**：
- 可用 → 走 Day 2 的 H5 部署路线
- 不可用（后端拒绝本地身份）→ 跳 Day 2 改走"体验版 + 体验成员"路线

### Day 2 — 把试玩版本放到公网（H5 路线）

1. 静态托管三选一：阿里云 OSS 静态托管 / Vercel / Cloudflare Pages。
2. 上传 `app/dist/build/h5` 全部内容，拿到 https 链接。
3. 手机实测：微信内打开、系统浏览器打开各一次。

**完成标志**：陌生人拿到链接能直接打开并进入游戏。

**回滚**：托管侧删除即可，不影响任何本地环境。

### Day 3 — 反馈入口

1. 游戏结束页加「说说你的感受」按钮（问卷链接）。
2. 小程序端再加一个原生反馈入口（`<button open-type="feedback">`）。
3. 问卷只问三个问题：好不好玩、哪里卡住了、会不会再玩。

**完成标志**：试玩者点两下就能留下反馈，问卷能收到回执。

### Day 4 — 体验版（微信内真机验证）

1. 后台把当前版本设为体验版，添加体验成员。
2. 每人扫码进一次，重点看：小程序码能否扫码进房、实时同步是否稳定。

**完成标志**：体验成员在真实微信环境里完整玩完一局。

> 体验版与 H5 并行存在，二者不冲突：H5 拉样本，体验版验真实环境。

### Day 5 — 本机跑通自建 Supabase（为长期铺路）

1. 复制一份独立目录（或新 clone），在那里面起 docker-compose 版 Supabase。
2. 按编号顺序执行 26 支迁移。
3. 客户端指向本地实例（改 `.env.local`），跑一次联机。

**完成标志**：本地自建实例上，四玩法能跑一局，数据能落库。

**回滚**：删除容器与目录，主项目未受影响。

### Day 6 — 试用 ECS 部署（可选，视 Day 5 结果）

1. 开阿里云试用机（香港，2 核 4 G，按量付费，按需开机）。
2. 把 Day 5 的 compose 原样搬上去，绑域名、配 HTTPS。
3. 客户端改两个环境变量验证。

**完成标志**：公网地址能完成一局游戏。

**注意**：试用机是**按量付费实例，不能备案**，因此只用于验证，不作为正式发布后端。

**回滚**：停机即停费，客户端环境变量改回云端地址。

### Day 7 — 出可试玩版本并做回滚演练

1. 汇总两条通道：H5 链接 + 体验版二维码。
2. 写一页《试玩说明》：怎么进、怎么开局、遇到问题找谁。
3. **做一次完整回滚演练**：从 `v1.0-验收版` 重新构建一次，确认能跑。

**完成标志**：拿到链接的人能玩；演练过的回滚路径成立。

## 4. 决策点（遇到就停一下再决定）

| 节点 | 判断 | 走向 |
| --- | --- | --- |
| Day 1 结束 | H5 能否联机 | 能 → H5 路线；不能 → 体验版路线 |
| Day 5 结束 | 自建 Supabase 是否稳定 | 稳 → Day 6 上 ECS；不稳 → 推迟，先出试玩版 |
| 一周结束 | 反馈里是否出现"卡顿/断线"集中反馈 | 出现 → 优先修实时通道，不再加功能 |

## 5. 风险与预案

| 风险 | 影响 | 预案 |
| --- | --- | --- |
| H5 身份不被后端接受 | 无法联机试玩 | 走体验版路线；或 H5 只开单机部分 |
| 两人同时改同一文件冲突 | 阻塞 | 每人在自己分支改，合并前先 `git pull --rebase` |
| 试用机额度用尽 | 服务中断 | 按需开机，用完即停；本地/云端环境随时可回退 |
| 迁移脚本在自建实例上报错 | 验证失败 | 逐支执行并记录，只在新环境处理，不动云端 |
| 试玩期间数据错乱 | 影响体验 | 试用期使用独立数据库，不接正式数据 |

## 6. 一页速查

```bash
# 回到验收版
git checkout v1.0-验收版 && cd app && npm ci && npm run verify

# 本地开发
cd app && npm run dev:mp-weixin     # 小程序
cd app && npm run dev:h5            # 浏览器

# 出包
cd app && npm run build:mp-weixin   # → dist/build/mp-weixin
cd app && npm run build:h5          # → dist/build/h5

# 质量门（提交前必跑）
cd app && npm run verify
```

**验收线**：任何一步完成后，`npm run verify` 都必须仍然全绿；不绿就先修再往下走。
