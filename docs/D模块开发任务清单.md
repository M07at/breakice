# D 模块开发任务清单

## 负责范围

D 模块负责大厅、用户体验、统一视觉规范、主持人/玩家端布局、真心话大冒险和微信分享入口。

课程教案中的“需求分析报告、设计报告、测试报告、最终汇报”等是项目交付过程要求，不直接作为前端页面需求；页面和接口以需求分析文档、软件设计文档为准。

## 接入规则

1. 页面只负责展示和发起动作，最终权限与游戏状态以 RPC/Realtime 服务端结果为准。
2. 不在 D 模块前端写 Supabase service role key、AI API key 或 RLS 绕过逻辑。
3. `Room`、`Player`、`GameType` 等公共类型集中放在 `app/src/types/room.ts`，联调前先统一字段命名。
4. Mock 服务和真实服务保持同一组函数签名，便于本地演示和后续替换。
5. 新增游戏玩法时优先复用 `surface`、`btn`、`PlayerList` 等现有设计 Token 和组件。
