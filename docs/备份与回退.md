# 数据备份与回退

## 哪些数据必须能恢复

| 数据 | 丢了会怎样 | 覆盖方式 |
| --- | --- | --- |
| `profiles` 的昵称 / 形象 | 用户要重新捏一遍 | 快照 + 合并回灌 |
| `word_banks` / `word_bank_items` | 自建题库没了，没法重建 | 快照 + 合并回灌 |
| Storage `artworks` 桶里的画作 | 历史画作打不开 | Supabase Storage 自带备份（见下） |
| `rooms` / `games` / `scores` | 过程数据，重开一局即可 | 不进快照 |

`auth.users` 由 Supabase 自己管理，不要手工改；真要迁移用官方备份。

## 打快照

在 **SQL Editor** 里执行：

```sql
select public.create_backup('上线前');   -- 返回快照 id
select * from public.list_backups();     -- 看有哪些、多大、多少题
select public.export_backup('<id>');     -- 取出完整 JSON，另存到仓库外
```

建议时机：**每次批量导入题库之前**、**上线/演示前**、**改题库结构之前**。

## 回退（合并式，不删数据）

```sql
select * from public.restore_backup('<id>');
-- banks_restored / items_restored / profiles_touched
```

语义是**只补缺失**：

- 题库按 `id` 匹配，已存在的不覆盖（避免把刚改好的内容回退成旧版）
- 只恢复 `owner_id` 还在的题库，避免外键失败
- profiles 只在昵称为空的默认值、或没有头像时才写入

如果确实要"清空重来"，本方案不提供——那种操作必须人工确认，建议先导出 JSON，再手工 `delete`。

## 清理旧快照

```sql
select public.prune_backups(30);   -- 删掉 30 天前的快照
```

建议每月跑一次，或把它加进数据库定时任务。

## 权限

`backups` 表开了 RLS 且没有任何策略，四个函数也 `revoke from public`：
**只有 SQL Editor（postgres）和 service_role 能调用**，客户端拿不到任何题库快照。

## Storage 画作

`artworks` 是私有桶。Supabase 免费版不提供对象级历史备份，建议：

1. 重要演示前，在 Dashboard → Storage → `artworks` 里手动下载需要保留的对象；
2. 或升级到包含 PITR / 每日备份的套餐；
3. 画作本身是过程产物，丢失不影响对局——`artworks` 表里没有对应对象时，画廊会退回占位文本，不会报错。

## 回退演练（建议每次发版前做一次）

```sql
-- 1. 打快照
select public.create_backup('演练');

-- 2. 模拟误删（删掉一个自建题库）
delete from public.word_banks where owner_id is not null
  and id = (select id from public.word_banks where owner_id is not null limit 1);

-- 3. 回灌
select * from public.restore_backup((select id from public.backups order by created_at desc limit 1));

-- 4. 确认题库回来了
select count(*) from public.word_banks where owner_id is not null;
```
