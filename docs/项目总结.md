## 一、这个项目是什么

四个人协作的微信小程序「破冰局」：一群人在一个房间里，由主持人挑选玩法，所有人一起玩一局，结束后回到大厅再来一局。

| 角色 | 负责 |
| --- | --- |
| 我（D） | 大厅 / 房间壳 / 真心话大冒险 / 形象系统 / **整合联调** |
| C | 谁是卧底引擎 + 题库 |
| B | 你画我猜画布 + 计分 |
| A | Supabase 后端（表、RPC、存储、Realtime） |

技术栈：uni-app 3 + Vue 3 + TypeScript + Vite + Pinia，主端 `mp-weixin`，副端 H5；后端 Supabase（PostgreSQL + RLS + RPC + Storage + Realtime + Edge Functions）。

## 二、整合：把四条独立开发的支线接成一条流水线

### 2.1 第一件事是统一"房间"的概念

三个模块各自假设了不同的运行模型：

- C 的引擎假设"一局游戏 = 一个 gameId"，不关心房间
- B 的画布假设"单机，本地抽词、本地计分"
- A 的后端同时提供了 `rooms`（大厅）和 `games`（对局）两套

整合的核心决定：**房间是唯一的组织单位**。

```
大厅 → 建房/加入 → 全员准备 → 主持人选玩法 → 房间进入 playing
  → 所有人进游戏 → 结束 → 房间回 lobby 且准备状态清零 → 再来一局
```

为此在客户端建立了一个**平台抽象层**，让三个模块用同一套接口访问后端：

```
app/src/platform/
├── types.ts       RoomApi 接口（建房、加入、准备、开局、结束…）
├── supabase.ts    SupabaseRoomApi：手写 REST over uni.request
├── local.ts       LocalRoomApi：纯内存版，离线开发与单测用
└── realtime.ts    Realtime 客户端（Phoenix 协议 + 心跳 + 退避重连）
```

好处是：**离线也能开发和跑测试**，联机只是换一个实现。

### 2.2 三个模块各自怎么接进来

| 模块 | 接入方式 | 关键改动 |
| --- | --- | --- |
| **C 谁是卧底** | 服务端权威：一局的所有状态存在 `games`，客户端通过 `uc-command` Edge Function 发指令 | 引擎打包进 Edge Function；客户端只保留一个 `UcPlayerPort` 适配器 |
| **B 你画我猜** | 早期是单机引擎，联机时**主持人跑引擎、其他人只读视图** | 主持人用 `ChunkPump` 把笔画广播出去；其他端用观战画布重放 |
| **A 后端** | 22 支迁移 + 4 个 Edge Function | 补了若干 RLS 策略、授权、以及一个"房间作用域"函数 |

### 2.3 你画我猜做了两套形态

这是整合里最费力的部分，因为 B 的引擎是单机的，而产品要两种联机玩法：

**形态一：纯你画我猜（`pages-draw/live`）**

```
主持人：本机跑 LocalDrawRoomBackend（真实房间名单）→ 每 500ms 发布视图 → 轮询指令队列
其他人：只读视图，交画/发言通过指令队列回传
```

**形态二：你画我猜谁是卧底（融合玩法，接力画）**

```
每轮：所有人共用一块画板，按发言顺序依次接力作画
      每人画完自动提交一份快照（作品键 = 轮次#玩家）
轮末：按顺序展示每人的快照 + 一张「完整接力画」→ 投票
```

实时画板全程可见：作画者广播笔画分片，其他人用观战画布重放，并每 4 秒要一次全量快照兜底。

### 2.4 联机链路：三条通道各司其职

| 通道 | 用途 | 实现 |
| --- | --- | --- |
| **轮询** | 保底，所有人都在用 | 房间 2 秒、对局 1 秒 |
| **Realtime 广播** | 让别人"立刻"刷新 | `pokeRoom(event)`，收到就立刻拉一次 |
| **指令队列** | 把"观战者的操作"交给主持人 | `post_draw_action` / `take_draw_actions` |

没有依赖 WebSocket 做正确性——断线了轮询照样能跑，只是慢一点。这是刻意的取舍：小程序里 WebSocket 不稳定，正确性不能押在它上面。

### 2.5 后端：22 支迁移与 4 个函数

```
migrations/
├── 0001–0008   表结构、RLS、RPC、授权补丁
├── 0009–0013   形象字段、房间设置、回填 openid
├── 0014  truth 共享回合
├── 0015  备份
├── 0016  微信 token
├── 0017  你画我猜会话与指令队列
├── 0018  私有题面（谁是卧底融合玩法）
├── 0019  开局写 game_type
├── 0020  每轮重置准备 + 房主退出关房
├── 0021  同一轮多人各交一幅画
└── 0022  AI 评分增加猜测结果与用时
```

Edge Functions：`wechat-auth`（登录自愈）、`uc-command`（谁是卧底全部指令，内联打包引擎）、`ai-score`（AI 评分）、`wechat-qrcode`（小程序码）。

## 三、美术

### 3.1 形象系统（雪人是自己一笔一笔画的）

首页可以捏一个雪人代表自己：**颜色、身体、眼睛、嘴巴、帽子**五个分层，全部为手绘素材，组合后成为个人头像。

- 形象存在 `profiles.avatar`，房间列表、成员列表、颁奖台处处复用同一份
- 组件 `Avatar.vue` 负责分层叠加，尺寸可变
- 这是个"零成本但有效"的设计：不用上传图片、不用审核，四个人也能一眼分清

### 3.2 其他素材由 AI 生图 + 人工挑选

- 全局背景图：AI 生成 → 压成 1080 宽 JPEG（1571 KB → 117 KB）
- 图标、装饰元素：AI 生成后人工挑

### 3.3 视觉统一

建立了一套设计 token（`styles/tokens.scss`）：

| token | 用途 |
| --- | --- |
| `--brand` / `--brand-deep` / `--brand-soft` | 主色（浅蓝）与浅底 |
| `--mint` / `--warning` / `--danger` | 状态色 |
| `--ink` / `--muted` / `--line` | 文字与分割线 |
| `--surface` / `--canvas` | 卡片底 / 页面底 |
| `--radius-md` / `--radius-lg` / `--shadow` | 圆角与阴影 |

把四个模块写死的颜色逐步替换成 token，包括 C 的 `classic.css`（原是一套墨绿+米色）、B 的 `pages-draw` 与题库页。

**踩到的一个坑**：微信 **WXSS 不允许引用本地图片**做背景（`app.wxss:1:48 本地资源图片无法通过 WXSS 获取`），只能 base64 内联。最终把背景图 base64 进 `styles/background.css`（160 KB），产物从 0.81 MB → 0.96 MB，仍在 2 MB 限内。

## 五、调试纪实：17 个真实 bug

按"症状 → 根因 → 修法"记录，这些是整段工作里最有价值的部分。

| # | 症状 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 房间页点不动 | 旧 `canvas-id` 二维码是原生组件，吞掉点击 | 改用 `canvas type="2d"`，二维码挪到独立页 |
| 2 | `showModal` 无反应 | `confirmText` 超过 4 字 | 去掉按钮、改自动补位 |
| 3 | 编译报 `game.json` 缺失 | 注册成了**小游戏**账号 | 重新注册小程序账号 |
| 4 | 真机请求全失败 | 域名未备案、不在合法域名列表 | 开发调试模式绕过（长期需备案） |
| 5 | 别人交的画被拒 | `drawRemote` 没把 `action.userId` 传给后端 | 补上发言人 |
| 6 | 手机看不到自己的词 | 引擎只给"本机画者"下发词 | 新建私有题面表 + RPC |
| 7 | 猜对没反馈 | 消息要绕服务端一圈才回来 | 本地先比对、立即提示 |
| 8 | 第二轮上传 400 | 错误被截断看不到原因 | 带上响应体；路径加时间戳 |
| 9 | 客人进不了游戏 | `uc_start_game` 没写 `game_type` | 0019 一并写；客户端加兜底探测 |
| 10 | 一局结束不退大厅 | 缺重置逻辑 | 服务端清 `ready`；客户端自动返回 |
| 11 | 房主退出别人卡住 | 只做了房主转移 | 改为房主退出即关房，其他人回主界面 |
| 12 | 人机把整局瞬间跑完 | `settleDeparted` 把机器人当"已退房"摘掉，胜负条件立刻成立 | 机器人豁免 |
| 13 | 加时赛刷 400 | 机器人投给非候选人 | 只在候选人间选；动作失败不再拖垮 tick |
| 14 | 4 人局死一个就结束 | `checkWinner` 里 `alive <= 3` 判卧底胜 | 按规则改为"平民全出局/只剩两人" |
| 15 | 加时赛全员弃权 | 候选人被排除在投票人之外 | 候选人也有投票权 |
| 16 | 每轮只有一幅画 | `artworks` 唯一键是 `(game_id, turn_key)` | 0021 扩到三元组；提交键带玩家 |
| 17 | AI 打分不落库 | 写的是 `score`，列名其实叫 `total`，且 update 没查 error | 改列名；测试脚本通过 ≠ 数据落库 |

另外两个"环境级"教训：

- **改了引擎忘了重新打包** `uc-command` → 线上规则不变，测试全绿。后来加了 `check:bundle` 在 verify 里拦截。
- **隧道地址会变**：trycloudflare 每次重启换域名，`AI_BASE_URL` 不更新就永远超时。

## 六、关键决策与取舍

| 决策 | 理由 |
| --- | --- |
| 房间为唯一单位，游戏只是房间的一个阶段 | 三个模块本来各玩各的，没有房间就串不起来 |
| 轮询为正确性兜底，Realtime 只做"加速" | 小程序 WebSocket 不稳定，不能把正确性押上去 |
| 谁是卧底规则放服务端（Edge Function 内联引擎） | 客户端可篡改；服务端权威才能防作弊 |
| 你画我猜由主持人跑引擎、其他人只读 | B 的引擎是单机的，改造成本最低的联机方式 |
| AI 评分放服务端、异步 | 模型慢（首帧 30 秒+），不能阻塞游戏 |
| 背景图 base64 内联 | 微信 WXSS 不支持本地图片，且域名未备案不能用网络图 |
| 词库清洗到 drawzy 能识别的 45 类 | 否则"AI 猜中"永远不成立，评分毫无意义 |
| 人机补位只用于测试 | 正式版不应出现，但两个人也能测 4 人玩法 |

## 七、美术与形象的细节

- **雪人五分层的组合数**：5 个部位 × 若干备选 = 几百种组合，足够区分小团体成员
- **配色收敛**：主色从最初的深靛蓝 `#4f46e5` 换成浅蓝 `#4f8ef7`，和 start 页的浅色调统一
- **同名玩家**：一律显示「昵称 #座位号」并按座位上色（6 色循环），解决"两个小明分不清"
- **颁奖台**：前三名带雪人形象 + 奖牌，其余用表格；金/银/铜三档底色区分
- **背景**：AI 生成，全局铺底，页面容器透明化才能露出来（这点被不透明底色盖住过，排查了一轮）

## 八、遗留问题

| 项 | 影响 | 建议 |
| --- | --- | --- |
| **4 人真机全流程未跑** | 规则和接力只在 2 真人 + 2 人机下验证；4 人时卡片是否挤、颁奖台如何排未知 | 凑齐四人跑一遍，这是唯一没被真实覆盖的路径 |
| **ICP 备案** | 正式发布必需；体验版不受影响 | 提前启动，周期 1–3 周 |
| **drawzy 隧道地址漂移** | 每次重启电脑要更新 Secret + 重新部署 `ai-score` | 注册 Cloudflare 固定隧道，或备案后用固定域名 |
| **B 的布局层只统一了颜色与圆角** | 间距、按钮尺寸未逐页调 | 视觉验收时逐页过 |
| **人机不画** | 融合玩法里机器人回合是空的 | 已确认不进正式版，可不处理 |
