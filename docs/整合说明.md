# 整合说明（D + C 合并）

本文记录把 D 模块（大厅 / 用户体验 / 真心话大冒险）与 C 模块（谁是卧底、题库、工程体系）合并成同一个微信小程序的实际情况，包括做了什么、没做什么，以及怎么跑。

- 整合分支：`feature/integration`
- 基线：`ca79460`
- D 提交：`f48a242`（`feature/d-lobby-avatar-game`）
- C 提交：`8c67d7c`（`origin/master`）
- 全程没有推送 Gitee，没有 `reset --hard` / `clean -fd`，也没有覆盖任何一方提交。

## 1. 项目结构（整合后）

```
app/src/
├── components/        D：Avatar、AvatarEditor、PlayerList、RoomCodeCard
├── pages/             D：home、create、join、room、game（主包）
├── services/          D：roomService、avatarService、truthOrDareService、gameEntry、realtimeService
├── stores/            D：room（Pinia）
├── styles/            D：tokens.scss 设计系统
├── types/             D：room 数据类型
├── modules/
│   ├── undercover/    C：引擎、规则、玩家端口、后端契约
│   ├── bank/          C：题库仓储、导入导出、校验、548 条题库
│   ├── local/         C：本地会话、题库适配、联调端口
│   └── shared/        C：随机数工具
├── pages-uc/          C：谁是卧底 / 你画我猜谁是卧底（分包）
└── pages-bank/        C：题库管理（分包）
```

`app/dev/` 是 C 的本地联调服务（只在 `vite serve` 生效，不进小程序包）。

## 2. 配置整合决策

| 文件 | 决策 |
| --- | --- |
| `app/package.json` | 保留 D 的运行时（uni-app `3.0.0-5030320261023001`、vue `3.4.21`、pinia `2.1.7`）与 `type: module`；并入 C 的 vitest、质量脚本与 `overrides` 审计锁定；新增 `@` 别名所需依赖不变 |
| `app/package-lock.json` | 删除冲突文件后由 `npm install` 重新生成 |
| `app/src/pages.json` | 主包保留 D 的 5 个页面作为入口；C 的 `pages-uc`、`pages-bank` 作为分包接入；删除 C 的开发占位页 `pages/index/index`（其注释要求大厅做好后删除） |
| `app/src/manifest.json` | 保留 D 的 `__UNI__BREAKICEHALL`、版本号与微信 `urlCheck/es6/minified`；并入 C 的 `lazyCodeLoading`、`optimization.subPackages` 与其它平台配置 |
| `app/vite.config.ts` | 以 D 的 uni 插件兼容写法为入口，加 `@ → src` 别名与 C 的 `c1PreviewPlugin()`；`vue → uni-h5-vue` 仅在 `UNI_PLATFORM=h5` 时生效，避免影响小程序编译 |
| `app/tsconfig.json` | 合并 `@/*` 路径映射、`vite/client`/`node` 类型，并把 `dev/`、`vitest.config.ts` 纳入检查范围 |
| `app/src/App.vue`、`main.ts` | 统一入口：保留 D 的设计系统与 Pinia |
| `app/index.html` | 采用 uni-app 官方 H5 模板占位符，标题保留「破冰局」 |
| `README.md` | 合并双方文档，补充目录归属与整合状态 |

未升级 uni-app / Vue / Vite 等核心依赖版本。

## 3. 已经接通的部分

1. **小程序入口**：`pages/home/index` 为启动页，创建 / 加入房间、房间等待区、玩家列表、房间码卡片、自定义头像、真心话大冒险全部沿用 D 的实现。
2. **大厅与房间进入 C 模块**：房间等待区主持人控制台新增「谁是卧底」「你画我猜谁是卧底」「题库管理」三个可用入口；首页新增题库管理入口。
3. **玩家名单打通**：`app/src/services/gameEntry.ts` 把房间玩家按座位顺序转成昵称，带入 `/pages-uc/setup`、`/pages-uc/hybrid` 的 `names` 参数，C 的开设页据此预填座位（1 号位仍为主持人），玩家不用重复输入昵称。
4. **题库统一**：谁是卧底、融合玩法、真心话大冒险共用 C 的题库仓储。真心话大冒险现在从 `modules/bank/seed/truth.json`（69 条）与 `dare.json`（52 条）抽题，并会在可用时并入主持人自建的 truth/dare 题库；题库不可用时回退到原内置 8 条。
5. **题库规模**：`undercover-pairs` 157 + `english-pairs` 60 + `draw-words` 210 + `truth` 69 + `dare` 52 = **548 条**（其中中文原创 488 条，加 60 条英文词对）。
6. **设计变量在微信端可用**：D 的 `styles/tokens.scss` 从 `:root` 改为 `page`，因为 WXSS 不支持 `:root`；H5 构建时 uni-app 会映射到 `uni-page-body`，两端都已验证生效。

## 4. 尚未实现（明确标注，不是完成状态）

1. **微信小程序内的多人实时同步还没接通。** C 的引擎本身支持固定玩家的多设备流程，但传输层目前只有 `app/dev` 里的本地联调服务（`/__c1_mock/*`），它只在 `npm run dev:players` 的 H5 预览里可用。真实实现是 A 模块的 `UcPlayerPort`。
2. **因此小程序里点「创建多设备联调游戏」会提示需要 H5 预览**，开设页已在小程序端显式标注这一点。房间 → C 页面的入口、座位预填、题库都已经就绪，缺的只是传输实现。
3. **融合玩法的画布是 C 的模拟适配器**（`MockDrawingAdapter.vue`），真实画布、笔画同步与 AI 评分属于 B / A。
4. **「你画我猜」（B 的游戏）仍是待接入占位。**
5. **头像只在 D 的页面展示**：C 的玩家快照只有 `id` / `name`，没有头像字段，所以谁是卧底页面内不显示 D 的自定义头像。
6. **房间与在线状态仍是 D 的 Mock service**（`services/roomService.ts`），没有 Supabase RPC / Realtime / 微信登录。
7. **Gitee CI 未激活**：`scripts/ci.sh` 与 `.gitee/ci-job.json` 只是可执行脚本与配置说明，需要仓库管理员在 Gitee 后台绑定。

## 6. 运行方式

```powershell
Set-Location D:\1\break-ice-hall\app
npm install
npm run dev:mp-weixin      # 微信小程序开发（用微信开发者工具导入 app\dist\dev\mp-weixin）
npm run build:mp-weixin    # 微信小程序构建
npm run dev:h5             # H5 预览
npm run dev:players        # H5 多设备联调（谁是卧底 / 融合玩法需要它）
npm run type-check
npm run test
npm --prefix app run verify   # 在仓库根目录跑完整流水线
```

微信开发者工具导入目录：

- 构建版：`D:\1\break-ice-hall\app\dist\build\mp-weixin`
- 开发版：`D:\1\break-ice-hall\app\dist\dev\mp-weixin`

AppID 在 `app/src/manifest.json` 的 `mp-weixin.appid` 填写；留空时开发者工具可用测试号预览。
