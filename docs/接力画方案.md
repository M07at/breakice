# 接力画（你画我猜谁是卧底）方案

定稿日期：2026-11-05。替换原来「一轮只有一幅画」的实现。

## 玩法

```
第 N 轮，公共画板从空白开始
  玩家 A 画 → 提交 → 快照 A
  玩家 B 在 A 的结果上继续画 → 提交 → 快照 B
  玩家 C 在 B 的结果上继续画 → 提交 → 快照 C
  …
本轮结束
  → 依次展示 快照 A → B → C（能看出每个人加了什么）
  → 再展示一张完整的接力画（最后一个人的快照）
  → 投票
```

**实时画板保留**：作画过程中所有人都能看到当前笔迹，这样能看清"谁画了什么"。

## 三个关键点

### 1. 续画用矢量，不用贴图

每位玩家开始时，把本轮**已有的笔画数据**（`DrawOp[]`）灌进自己的画布引擎，再继续画。
路线 A：`engine.loadSnapshot(ops)`。

- 缩放不变形，撤销/清空只影响自己的这一层
- 复用 `modules/draw` 已有的 `snapshot()` / `loadSnapshot()`

### 2. 每人的快照要分开存

数据库原来是 `unique (game_id, turn_key)`，同轮只允许一张，第二个人会覆盖第一个。
`0021_artworks_per_player.sql` 改成 `unique (game_id, turn_key, user_id)`，
并同步 `submit_artwork` 的 `on conflict` 目标。

客户端提交键用 `轮次#玩家`（如 `2#<user_id>`），画廊按轮次前缀匹配（`#` 和 `-pk` 都要认）。

### 3. 展示顺序

- 投票/回顾阶段：本轮所有快照，按 `created_at` 升序，标注「第 1 位 / 第 2 位…」
- 结束阶段：整局所有轮次
- 「完整接力画」= 本轮最后一份快照，单独突出展示

## 已知风险

- 玩家 B 挂载时若还没收到 A 的全量笔画（实时通道抖动），会从空白开始画。
  兜底：挂载时用 `op=current` 的快照里带的 `ops` 初始化，而不是只依赖广播。
- 唯一键改动影响历史数据：旧行的 `user_id` 已存在，迁移不会丢数据。

## 验收

1. 两人各画一笔，投票页看到**两张快照**，顺序正确
2. 第二个人能看到第一个人的笔迹并在其上继续
3. 结束页有「完整接力画」
4. `npm run check:drawroom`、`npm run check:uc` 仍全过
