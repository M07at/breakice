# C2 P0/P1 融合玩法与适配合同

本轮采用可评审默认规则，未声称团队已批准AI权重等未决策事项。

## 流程
每人独立领词并确认 → 存活者按顺序作画（每人25秒）→ 作品回顾10秒 → 各自投票30秒 → 淘汰/平票加赛 → 下一轮或终局。

使用现有相近词对，仅抽drawable=true的词对；融合玩法4–12人。角色、词语隐私、白板、平票加赛、退出资格、胜负和最大轮数继承普通卧底。投票选卧底玩家，不是猜某个词。AI仅影响已有引擎的附加奖励，不改变阵营胜负；统一计分系统仍归B。

## P0交付
- 删除传手机玩法及页面，所有玩法使用固定身份。
- 私密词卡、当前画手与只读等待、模拟作画提交、公共作品回顾、投票、结果与再开。
- 共享预览服务保存画作，所有客户端获取一致快照；不在各客户端各自运行规则。
- MockDrawingAdapter通过editable与submit事件装配；不实现真实画布或笔画同步。

## P1交付
- 只有当前画手可提交，客户端不能代别人提交或覆盖已交作品。
- 同请求重复提交返回当前快照，不能生成重复作品或重复评分；同ID不同内容拒绝。
- 每张图模拟pending→success/failed/timeout。成功模拟分78，失败跳过，超时5秒跳过；评分返回不是阶段推进条件。
- 无人交画、网络断开、画手超时均按截止时间继续，不会卡在等待AI状态。
- 评分在终局才显示数值；新局不带上一局的作品和评分。
- 断线恢复、旧局次响应过滤、重试和固定身份继承C1；后端同一框架处理同步和幂等。

## 接口
UcPlayerPort.submitDrawing(gameId, drawing, meta)返回个人快照。drawing为开发适配器的preview图形和scoreMode(success/failed/timeout)；mock服务只接受四种测试图形。客户端不指定playerId。真实B画布应通过组件适配器提供作品引用，真实平台适配器在同一port方法中上传/关联该引用；当前模拟请求格式不宣称是A/B已确认的最终上传协议。

UcPlayerSnapshot.artworks包含id/playerId/turnKey/preview/status，成功分数仅在终局提供。普通轮和加赛用不同turnKey。作品回顾是引擎review阶段，客户端不自行决定进入投票。服务端内部评分入口不属于玩家动作。

## 验证
自动测试覆盖画手权限、同时重试、同ID冲突、成功/失败/超时、分数隐私、无人交画、回顾和投票、终局和清空重开。六浏览器联调覆盖独立词卡、轮流模拟作画、公共画廊、个人投票、离线恢复、结果及同步重开。真实微信设备、B画布和A真实AI仍需后续联调。
