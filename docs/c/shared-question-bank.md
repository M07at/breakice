# C3 P0/P1 与两款游戏独立页面

## 路由
普通卧底设置 /pages-uc/setup，个人游戏 /pages-uc/player。
融合玩法设置 /pages-uc/hybrid，个人游戏 /pages-uc/hybrid-player。
首页分别有两个入口。页面不提供切换玩法的选择器，但共享内部组件、身份接口和题库仓库，避免两套逻辑发生漂移。

## 共享数据
两个游戏都从同一个 undercover 题库集合读取。系统库包含原有157对中文及60对常用英文。普通玩法按语言筛选；融合玩法额外筛选drawable=true。自定义题目只需维护一次；修改在下次开局/重开时生效，不改变已分配的词语。

H5预览中的题库管理、抽题与多设备服务使用同一个C3BankStore/BankRepository。自定义数据保存在 app/.c3-data/banks.json（已忽略Git），系统库从种子代码加载。自定义库跨浏览器共享，重启后从该文件恢复。数据库文件使用临时文件写入后替换；不要提交或删除自己的数据文件。

这是开发用持久化JSON数据源，不宣称已接入Supabase或生产数据库。所有开发浏览器共用local-host工作区编辑身份。生产登录身份、RLS和实际数据库连接仍需A提供；BankRepository接口可替换。微信小程序构建可以运行界面，但真实平台数据库尚未联调。旧版仅存在浏览器存储中的自定义库不会自动覆盖服务端数据，旧存储键保留，可按JSON/CSV格式导入。

## P0
内置中文/English词对无需导入即可使用。设置页选择词语语言（默认中文），记住偏好；不会翻译整个应用。每次从所选语言和题库随机抽相关词对。已用词对优先排除；匹配范围耗尽时提示重新洗牌。词库不足或融合无可画题目时给出错误，不静默切换语言。

## P1
题库管理支持增删改查、只读系统库、按游戏分类、语言/难度筛选、词语或分类标签搜索、分批显示、JSON/CSV导入导出和错误行提示。语言用tags中的lang:zh / lang:en保存，沿用现有CSV/JSON格式；旧中文条目兼容自动识别。表单单独选择语言并保存标签。重复编辑被拒绝；非法批量写入先全部验证，不留下半批数据。导入/导出保留语言、标签、难度和可画标记。

## 运行与评审
在 D:\Software Project\app 执行 npm run dev:players。首页分别打开两款游戏的设置页。选English，创建后只会得到英文词；选择中文则只抽中文。每人仍使用自己的邀请链接。

从任一设置页打开管理共享题库，创建“undercover”自定义库，添加如sun/moon并选English与可画。回到两款游戏分别选中该库，均可抽到同一份数据。取消可画后，普通玩法仍可用，融合会报告无可画词对。修改后重新开局才生效。

测试包含语言隔离、同库双玩法、默认中英文、无重复直到耗尽、CSV/JSON往返、快照恢复、只读/所有者规则、原子校验与编辑去重。浏览器检查覆盖分开的设置与游戏URL、记住English、双玩法读取同一自定义库、共享编辑器。真实微信设备和生产权限不在这些模拟测试结论内。
